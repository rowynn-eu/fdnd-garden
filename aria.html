using Aria

i was sincerely confused about the usage of aria and what's it's intended use is supposed to be.

this happened as i had asked a question to Krijn , expecting an answer about how to properly use a section and using it with the aria-labelledby="section-title" attribute, thinking it was the right thing to do as I was led to believe by a video from Kevin Powell and other sources online using aria-label for functions.

colour me surprised when Krijn reacted confused, and negatively, as if i was talking about nonsense, which was perceded with a thoughtful, and civil discussion about ARIA and its use-cases.

why I learned it's bad practice

krijn swiftly directed me towards the first rule of ARIA, as proposed by the W3C (discontinued) draft:

if you can use a native HTML element or attribute with the semantics and behavior you require already built in, instead of re-purposing an element and adding an ARIA role, state or property to make it accessible, then do so.

under what circumstances may this not be possible?

  • if the feature is available in HTML but it is not implemented or it is implemented, but accessibility support is not.
  • if the visual design constraints rule out the use of a particular native element, because the element cannot be styled as required.
  • if the feature is not currently available in HTML .

from 2.1 First Rule of ARIA Use - W3C Discontinued Draft

he went on to explain that you'll only be using ARIA in projects that are severely complex, advanced or high in scope, and you're working to make a website function for the remaining 20%.

... which of course this website isn't. Anything written by hand won't be high-scope enough that it'll warrant the use of ARIA-label's.

i guess what's worse that it won't ever be covered in the curriculum of this programme because - (assuming here) -, most of the lecturers/teachers are Anti-AI aswell as Anti-ARIA.

but it makes sense, if you were to take a look at the WebAIM 2026 accessibility report , home pages with ARIA present had significantly more errors (59.1 on average) than pages without ARIA (42 on average).

genuinely, coulour me damned.

why it sucks to hear though...

i've always wondered what aria labels were about, and why they were used in certain websites and missing in others.

it's not that my interest in ARIA and accessibility come across as virtue signaling, or me pretending to care about visually-impaired users or those reliant on screen readers. It's out of a genuine interest.

so to be shut down like that, and learning that using ARIA (while the intentions are good) is looked down upon, it sucks.

what's the solution then if you want to make the web more accessible?
